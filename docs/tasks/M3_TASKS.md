> **来源**：`docs/ARCHITECTURE_BASELINE.md` §9 M3、§6（模型集成）（架构基线 v1.0）。
> **门禁前置**：G2 = GO（否则本里程碑全部任务 BLOCKED）。

## M3-T1 · 本地视频效果节点（P0 首个 AI 参与路径）

**1. Task ID 与目标**
实现第一个本地视频处理节点：appsink 取帧 → 本地处理（轻量滤镜，如亮度/叠加标记，选实现成本低者）→ appsrc 回注管线；节点可开关、可旁路；处理时延计入观测指标。

**2. 对应需求 FR / 架构 ADR**
- FR-004（单个 AI 节点处理模式）、FR-006、FR-007；ADR-002、ADR-007；基线 §6.1 P0、§9 M3-1；参考 [S7][S8]。

**3. 前置依赖**
G2 = GO。

**4. 允许修改的模块与文件范围**
- 修改：`runtime/gst-adapter/`（效果节点封装）、`runtime/media-core/`（节点注册与开关）
- 新建：`tests/integration/`（效果节点测试）

**5. 实施步骤**
1. 节点抽象：输入/输出 caps 声明、enable/bypass 接口（为 M3-T3 Provider 抽象做准备，但本任务不引入 manifest）。
2. 实现轻量滤镜（帧内像素操作，无模型依赖）；固定 720p 处理，帧时延预算写入文档。
3. 管线接入：appsink → 处理线程（有界队列）→ appsrc；队列上限与满时丢帧策略（记录丢弃计数）。
4. 开关与旁路：运行时切换 on/off/bypass，断言输出连续性。
5. 时延测量：节点输入→输出 PTS 差统计（p50/p95）。

**6. 自动化测试要求**
- 集成测试：开启/旁路/关闭三态输出断言；队列满丢帧断言；时延采样落盘。

**7. 真实环境验收要求**
- 在真实管线（含 M1 真机链路）中观察效果生效与旁路恢复原始画面（截图/帧统计留证）。

**8. 完成标准（DoD）**
- 三态行为正确；时延数据完整；无队列无界增长；§6.4 降级策略第 1 条（处理失败恢复原始画面）已实现并有测试。

**9. 风险及失败处理**
- 处理背压（R-05）→ 有界队列 + 丢帧 + 旁路；禁止无界堆积。
- 滤镜选择贪大（提前上分割模型）→ P0 只做轻量滤镜（§6.1 明文）；模型类留 M4+。

**10. 应保留的测试证据**
`test-results.json`、`perf.json`（时延分布）、`screenshots/`（效果前后帧）。

**11. 状态**：未开始

## M3-T2 · 本地音频效果节点（基础降噪/增益）

**1. Task ID 与目标**
实现本地音频效果节点：基础降噪（RNNoise 类轻量模型或算法型降噪，按许可与性能实测选定）或增益控制；可测、可切换、可旁路；音频旁路必须正常（§6.1 P1 要求）。

**2. 对应需求 FR / 架构 ADR**
- FR-004、FR-006、FR-007；ADR-007；基线 §6.1 P0（本地基础降噪）、§6.4（音频推理超时降级）、§9 M3-1。

**3. 前置依赖**
M3-T1（节点抽象就绪）。

**4. 允许修改的模块与文件范围**
- 修改：`runtime/gst-adapter/`（音频效果节点）、`runtime/media-core/`
- 新建：`tests/fixtures/`（带噪测试音频）、`tests/integration/`
- 第三方依赖（如 RNNoise）：走 SBOM 记录

**5. 实施步骤**
1. 候选实现评估（≥2 项：算法型 vs 轻量模型型）：许可证、CPU 占用、块大小匹配（10ms/480 样本）实测记录。
2. 接入音频管线：appsink → 处理 → appsrc，保持块时间戳连续。
3. 开关/旁路/故障（处理超时注入）三态验证：超时 → 恢复原始音频或静音（§6.4，按策略），**不可重放过期语音片段**。
4. 质量粗测：带噪测试音频降噪前后对比（客观指标：SNR 改善；主观记录留档）。
5. CPU 占用统计（NFR-10 基础数据）。

**6. 自动化测试要求**
- 集成测试：三态断言、超时注入断言、时间戳连续性、CPU 采样。

**7. 真实环境验收要求**
- 真实麦克风输入 + 真实输出端点链路上验证三态与降级；纯文件级测试只算单元证据。

**8. 完成标准（DoD）**
- 选型决策记录（含许可证）；三态与超时降级有证据；SNR 对比数据完整。

**9. 风险及失败处理**
- 模型许可不兼容商用（R-06）→ 换算法型实现；SBOM 记录保留。
- 降噪引入时延超标（NFR-04 复测点）→ 块大小/算法窗口调整并复测，超标如实记录。

**10. 应保留的测试证据**
`test-results.json`、`perf.json`（时延/CPU）、`licensing-sbom.json`、对比音频样本（调试开关 + 明确同意下短期保存，§11-5）。

**11. 状态**：未开始

## M3-T3 · ai-adapter：Provider Manifest、授权、取消/超时/健康、统一降级

**1. Task ID 与目标**
建立 `runtime/ai-adapter`：Provider Manifest schema（基线 §6.3 示例格式）、授权属性（privacy scope：local-only / explicit-cloud-consent）、取消支持、timeout、健康状态上报、统一降级行为（fallback: bypass 等策略的执行器）；Provider 生命周期状态机（§4.3 AIJob）。

**2. 对应需求 FR / 架构 ADR**
- FR-004、FR-007、FR-009；ADR-005（Capability 契约）、ADR-007（Provider 双路径）；基线 §4.2（MediaCapability）、§4.5、§6.2、§6.3、§9 M3-2。

**3. 前置依赖**
M3-T1（节点抽象）。

**4. 允许修改的模块与文件范围**
- 新建：`runtime/ai-adapter/`、`contracts/capability/`（Provider Schema v0.1）、`providers/mocks/`（测试替身 Provider）
- 修改：`runtime/media-core/`（授权联动）

**5. 实施步骤**
1. Manifest schema：id、api_version、kind、input/output、execution（native-in-process / native-isolated / remote-python）、privacy、supports_cancel、latency_budget_ms、fallback（§6.3 字段全集）。
2. Manifest 校验器（schema 校验 + 语义校验：输入输出类型可匹配）。
3. Provider 运行时包装：超时监控、取消传播、健康心跳、崩溃检测（隔离进程场景）。
4. 统一降级执行器：按 manifest.fallback 执行 bypass/占位/静音；执行结果事件化。
5. 授权联动：privacy != local-only 的 Provider 必须有显式授权才可 RUNNING；撤销 → CANCELLED + 缓存清理（§6.4 第 5 条）。
6. `providers/mocks/`：永远成功、必超时、必崩溃三种 mock Provider（供 M3-T6/T7 使用）。

**6. 自动化测试要求**
- Manifest 校验测试（好/坏样例）；降级矩阵测试（超时/崩溃/撤销 × fallback 策略）；AIJob 状态机表驱动测试。

**7. 真实环境验收要求**
- 用 M3-T1/T2 真实节点 + mock Provider 在真实管线中演练降级；**纯进程内单测不构成降级行为验收**。

**8. 完成标准（DoD）**
- Schema 与执行器入库；降级矩阵全绿；mock Provider 三件套可用；授权撤销语义（§6.4-5）有测试证据。

**9. 风险及失败处理**
- 过早设计「万能能力图」（R-10）→ 只做 §4.5 已声明的编排检查（Track/Caps、时延预算、权限），通用规划器不做。
- Python Worker 路径过早引入 → 本任务只留 manifest 的 execution 字段，隔离 Worker 实现留 M4（§6.2）。

**10. 应保留的测试证据**
`test-results.json`（降级矩阵）、`contracts/capability/` schema、`build.log`。

**11. 状态**：未开始

## M3-T4 · 本地 VAD/ASR 字幕语义事件

**1. Task ID 与目标**
接入本地 VAD + 流式 ASR（sherpa-onnx 为候选，经许可审查与性能实测）生成字幕语义事件（partial/final），写入语义事件通道；**媒体流不依赖 ASR 成功**——ASR 慢/挂不影响音视频输出（§9 M3-3 明文）。

**2. 对应需求 FR / 架构 ADR**
- FR-004（语义 Sidecar）、FR-006、FR-007；ADR-005（Semantic Track）、ADR-007；基线 §6.1 P1、§6.2（native 推理）、§4.4（语义事件时间区间）、§9 M3-3；参考 [S13][S14]。

**3. 前置依赖**
M3-T3。

**4. 允许修改的模块与文件范围**
- 新建：`providers/native/`（sherpa-onnx 适配）、`contracts/media/`（语义事件 v0.1 定义）
- 修改：`runtime/media-core/`（语义通道）、`apps/`（最小字幕查看调试工具，可选）
- 第三方依赖：sherpa-onnx + 模型权重 → SBOM

**5. 实施步骤**
1. 模型选型与许可审查：VAD 模型、ASR 模型（中英）——权重许可证逐个记录进 SBOM（§8：不得按「项目开源」推断权重可商用）。
2. VAD 接入音频管线（旁路观察，不影响输出）；ASR 流式接入（独立线程/隔离进程，有界输入队列）。
3. 语义事件定义：type（transcript.partial/final）、媒体时间区间、trace_id、confidence（可选）；**不得与原始采集时间混为一谈**（§4.4）。
4. 事件通道：独立于媒体帧通道，不阻塞实时媒体；通道有界。
5. 延迟策略：推理结果错过呈现窗口 → 丢弃或转非实时事件（§4.4），实现并测试。
6. 演练：kill ASR 进程/模型超时 → 音视频输出零影响（核心验收）。

**6. 自动化测试要求**
- 事件序列正确性（固定音频 → 期望字幕区间）；ASR 故障注入（kill/超时/慢速）× 媒体流不受影响的断言；通道有界性测试。

**7. 真实环境验收要求**
- 真实麦克风语音 → 真实字幕事件产出（记录延迟分布）；模型在真实 CPU/GPU 环境运行的资源占用数据（Arc 140T 的 ONNX EP 兼容性实测登记）。

**8. 完成标准（DoD）**
- 字幕事件可用且时间区间正确；ASR 故障不影响媒体流（断言证据）；模型许可记录完整。

**9. 风险及失败处理**
- 模型性能不达标/许可问题（R-06）→ 换模型或降级为「仅 VAD」；结论如实记录。
- 字幕文本成为注入源 → 本任务仅透传事件；防注入策略在 M4-T2 系统化（§11-6 分工）。

**10. 应保留的测试证据**
`test-results.json`（故障注入断言）、`perf.json`（ASR 延迟/资源）、`licensing-sbom.json`（模型权重）、字幕样例（脱敏，同意机制下）。

**11. 状态**：未开始

## M3-T5 · AI 音频替换 Output Track（合成测试音替身）

**1. Task ID 与目标**
实现「AI 生成的音频」作为独立 Output Track 的机制验证：以确定性合成测试音为第一替身 Provider，验证替换/混合模式、时间戳在统一时间域的携带（§4.4）、回声与重复讲话控制（§6.1 P2 要求的控制项）、旁路恢复原始音频。

**2. 对应需求 FR / 架构 ADR**
- FR-004（多个 AI 节点/AI 替换输出）、FR-006；ADR-005、ADR-007；基线 §4.4（AI 生成媒体时间戳）、§6.1 P2、§6.4（音频推理超时/授权撤销）、§9 M3-4。

**3. 前置依赖**
M3-T2、M3-T3。

**4. 允许修改的模块与文件范围**
- 修改：`runtime/gst-adapter/`（双输出路径切换）、`runtime/media-core/`（替换模式策略）、`providers/mocks/`（合成音 Provider）

**5. 实施步骤**
1. 合成音 Provider（mock）：按 manifest 声明（execution: native-in-process；privacy: local-only；supports_cancel: true）。
2. Output Track 机制：原始音频 Track 与 AI Track 并存，输出端按模式选择（原声 / 替换 / 混合），模式由 Policy 控制。
3. 时间戳对齐：AI 音频块携带统一会话时间域 PTS；块边界与原始流对齐测试。
4. 回声/重复控制：替换模式下抑制原声进入 AI 输入的路径验证（防止自激励），策略记录。
5. 降级：合成音 Provider 超时/崩溃 → 恢复原始音频或静音（按 Policy，§6.4-3）；禁止重放过期片段。
6. 权限撤销：AI 音频授权撤销 → AI Track 停止 + 清缓存；OS 设备是否输出静音由用户设置（§6.4-5）。

**6. 自动化测试要求**
- 模式切换矩阵测试（原声/替换/混合 × 故障注入）；时间戳连续性断言；撤销语义断言。

**7. 真实环境验收要求**
- 经 Track A 音频端点由真实录音应用听到替换/混合结果（录制留证）；纯进程内验证不足。

**8. 完成标准（DoD）**
- 替换机制可用；降级与撤销语义有证据；为 M4 端到端模型路径预留的接口不动 Device Bridge（§9 M3-4）。

**9. 风险及失败处理**
- TTS 真模型诱惑提前接入 → 本任务只做替身（§9 M3-4 明文）；真 TTS 属 P2 后续（M5+ 评估）。
- 替换模式回声回路 → 抑制路径测试钉死；失败则限制模式为替换非混合并记录。

**10. 应保留的测试证据**
`test-results.json`（模式矩阵）、`perf.json`、`screenshots/` 或录制样本（真机音频证据）、`security-checklist.md`（撤销项）。

**11. 状态**：未开始

## M3-T8 · 多 AI 节点串联模式验证（FR-004 完整覆盖）

**1. Task ID 与目标**
验证 FR-004 第四模式「多个 AI 节点处理」：旁路 → 单节点 → 多节点链（如 降噪→VAD/ASR、滤镜→采样理解）运行时切换；链路时延叠加可观测；任一节点故障 → 按策略整链或局部降级；总时延不得借助队列积压拖慢普通通路（§7 解释）。

**2. 对应需求 FR / 架构 ADR**
- FR-004（四模式全覆盖）；ADR-005、ADR-007；基线 §4.5（多节点路径）、§6.2、§7（新增时延与 AI 响应分离原则）、§12 R-05。

**3. 前置依赖**
M3-T1、M3-T2、M3-T3。

**4. 允许修改的模块与文件范围**
- 修改：`runtime/media-core/`（链式编排与降级传播）、`runtime/gst-adapter/`
- 新建：`tests/integration/`（多节点场景）

**5. 实施步骤**
1. 链式拓扑配置（配置驱动固定拓扑，不做通用规划器——§4.5「避免过度设计」）。
2. 模式切换矩阵：旁路→单→多→单→旁路，输出连续性断言。
3. 级联时延测量：每节点时延 + 链总时延分布（p50/p95）。
4. 节点故障传播：链中第 2 节点超时 → 该节点旁路、其余节点维持（或按策略整链降级），策略显式化。
5. 背压检查：慢节点不导致上游无界积压（NFR-07 断言复用）。

**6. 自动化测试要求**
- 模式矩阵与故障传播自动化；时延采样脚本。

**7. 真实环境验收要求**
- 多节点链在真实管线（真机输出）中运行并采样；Mock 节点与真实节点混合允许，但至少一条全真实链路。

**8. 完成标准（DoD）**
- FR-004 四模式全部有行为证据；级联降级策略明确；无积压。

**9. 风险及失败处理**
- 链式时延叠加超标 → 记录分布并给出预算表（每节点 max_expected_latency_ms 实测覆盖声明值，§4.2）；超标节点降级为可选。

**10. 应保留的测试证据**
`perf.json`（级联时延）、`test-results.json`（模式矩阵）、降级策略文档段。
